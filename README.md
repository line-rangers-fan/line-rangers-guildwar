# line-rangers-guildwar

LINEレンジャーのギルドランキング、メンバー名簿、ギルド戦攻撃チェックを共有する非公式サイトです。閉鎖予定の元サイトへの通信は行わず、名簿と共有の攻撃記録を自分のDBに保存します。自分用のチェックはブラウザー内に保存します。React + Node.js + SQLite で動作します。LINEおよびゲーム運営会社とは関係ありません。

## 公開サイト

https://line-rangers-guildwar.eagerowl2.chatgpt.site/guildWarCount

公開版はCloudflare WorkersとD1を使用し、名簿・共有チェックはD1に永続保存します。自分用のチェックはブラウザー内に保存します。ローカル版は引き続きNode.jsとSQLiteで動作します。既存のRender定義は代替の公開先として残しています。

公開版のビルド・検証は `npm run build:worker` と `node scripts/check-worker.mjs` です。ホスティング設定は `.openai/hosting.json`、DBスキーマは `db/schema.ts`、適用済みの生成SQLと履歴は `drizzle/` にあります。変更時は `npm run db:generate` で新しいマイグレーションを追加し、適用済みSQLは編集しないでください。

## 起動

Node.js 24以降を使用します。

```sh
npm ci
npm test
npm run build
npm start
```

`http://localhost:3000/guildWarCount` を開いてください。ランキングは `/guild-tracker` です。開発時は `npm run dev` を使います（画面変更後はブラウザーを再読み込み）。

## 実装した機能

- 実データのギルドランキング、国・地域とギルド名による絞り込み、上位100 / 500 / 全件表示。
- RangerbookのギルドID付きランキングに基づくレジェンド／マスターの階級フィルター。階級選択中は順位の範囲制限を外し、その階級の全対象を表示します。操作欄はスマホでもコンパクトに表示します。
- 名前順・レベル順の昇順／降順を切り替え、並び順をブラウザーに保存。レベル順のときだけL68・SL5などのゲーム内ランク表記を併記します。並び順の比較には通算値を使用し、ランク境界でも正しく並べます。
- 上位100・200・500ギルドから自分用の登録リストを作成。同じブラウザーでは再起動後も登録先・選択ギルド・並び順を維持します。別のブラウザーや端末には同期しません。
- 登録はブラウザー内だけの操作で共有ギルドを新設しません。同じギルドの二重登録を防ぎ、旧形式の選択情報は実在する上位ギルドに限って移行します。
- `/api/guilds?limit=500` で最大500候補だけ返し、名簿は選んだギルドのみ取得。チェック保存時は保存済み名簿で検証し、外部サービスを待ちません。
- 通常は自分用モードで、チェックをこのブラウザーだけに保存。設定の「共有リンクを作成」で共有モードへ移り、LINEなどに同じURLを貼ればギルド単位の共有チェック表になります。敵ギルドへの切り替え画面はありません。
- 共有URLは `?gid=ギルドID&share=1&day=対象日`。リンクを知っている人は編集でき、約15秒ごとに同期します。自分用のチェックは共有開始時に追加しますが、既存参加者のチェックを消しません。「自分用へ戻る」と元のブラウザー内記録に戻ります。
- 以前の登録済みギルドは、自分用の記録がまだない最初の1回だけ従来の共有チェックを引き継ぎます。新規登録者の自分用チェックは空から始まります。
- 表示順は「すべて」「攻撃済み」「未攻撃」。1回以上チェックした人を攻撃済みとし、選んだ状態を上にグループ表示します。メンバーは隠しません。名前検索は各グループに適用されます。日付の見出しまたはチェック操作で対象曜日を切り替え、対象日と表示順をブラウザーに保存します。
- 日本時間09:00で日付を切り替え。現在の水・金・日だけを表示し、週の集計・履歴切り替え・週残り列は表示しません。
- 自分用チェックはブラウザーへ即時保存。共有モードのチェックはサーバーへ保存し、ほかの参加者は15秒ごとに再取得。表示中は5分ごとにメンバー・一覧も再確認。
- 2回目をチェックすると1回目もチェック。1回目を解除すると2回目も解除。保存は明示的な真偽値なので再送で反転しません。
- ギルドごとの共有リンク、モバイル対応。
- 攻撃欄は水・金・日ごとに「1回目」「2回目」を明記し、それぞれを個別のチェックボックスで表示。スマホでも名前と全6枠を同時に確認できます。ギルド選択・ランキング・共有は常時表示の設定欄にまとめ、名簿の詳細だけ折りたたみます。多人数の名簿は縦スクロールで確認できます。
- 情報源の正常応答を永続キャッシュ。取得不能時は前回取得日時と警告を表示。

**攻撃結果をゲームから自動判定する機能ではありません。** ゲーム内で結果を確認した利用者が手動でチェックします。未チェックはこのサイトに未記録という意味です。

## 閉鎖後も継続する仕組み

- **通常運用では元サイト・元サイトのAPIに通信しません。** 一覧の予備取得先からも除去しました。
- 以前取得したメンバーのキャッシュは起動時に永続名簿へ自動移行します。元の取得日時を保ち、画面では保存名簿であることを表示します。移行済みの手動編集を起動時に上書きしません。
- 「名簿を管理」から追加・改名・削除・レベル・PVPランクを編集できます。既存の行で改名すると同じIDを保つため、攻撃記録を引き継ぎます。
- 名前の一括貼り付けと名簿JSONの保存・取り込みに対応。JSONには安定したIDを含めます。別ギルドへの誤取り込みは画面で拒否します。
- 登録先を選ぶとRangerbookの公開名簿を取得します。非対応・古いデータ・人数不一致・同名者を識別できない場合は推測せず、保存名簿を維持するか手動登録を案内します。
- ギルド一覧の取得先が停止しても、保存済みギルドや「ギルドを登録」で追加したギルドを使えます。新規インストール時にすべての外部サービスが停止していても、手動登録から運用できます。

**Rangerbookの公開データ配信を接続しています。公式APIではなく、Rangerbook側の収集元・閉鎖予定APIへの依存は未確認です。** 未登録ギルドは公開名簿を取得し、既存名簿は「公開名簿を取得」で利用を開始します。以後は画面表示・再読込時に30分キャッシュを通じて更新します。6時間以上古いスナップショットは反映しません。手動編集すると自動上書きを停止します。

公開名簿にはゲームUID・PVPランクがありません。名前が一致する既存行は保存IDを維持し、新しい名前にはゲームUIDとは別のアプリ用IDを発行します。改名は自動で同一人物に結び付けず、新規行になります。記録を引き継ぐ場合は既存の行を手動で改名してください。同名グループは人数とレベルが変わらない場合だけ既存行を維持し、それ以外は名簿全体の更新を見送ります。同じ名前の別アカウントへの交代は判別できません。

## データ取得元

| データ | 取得元 | 動作 |
| --- | --- | --- |
| ギルド一覧・順位 | `https://rangers.lerico.net/api/v2/guilds` | 15分キャッシュ、障害時は保存済み・手動登録一覧 |
| メンバー名簿 | `https://pvp-data.warmycat.com/guildwar_ranking.json` と `guildwar_data_{LEGEND,MASTER,DIAMOND}.json` | 名前・レベルを抽出、DB保存。ランキング15分・名簿30分キャッシュ。元サイトへの通信なし |
| 自分用の攻撃記録 | ブラウザーのlocalStorage | 他の端末や利用者には送信しない |
| 共有の攻撃記録 | 自分のSQLite／公開版D1 | 同じ共有URLで15秒ごとに同期 |
| 任意の自動名簿 | `MEMBER_SOURCE_URL` で明示設定する独立した取得元 | 未設定時はRangerbookを使用。手動編集済み名簿を優先 |

Lericoは第三者サービスであり、公式LINE APIではありません。今回の調査の詳細と旧実装の情報源は [docs/SOURCES.md](docs/SOURCES.md) に記録しています。コードはこのリポジトリ用に新規実装しています。

## バックアップ・復元

名簿JSONは名簿だけの持ち運び用です。攻撃記録・名簿・ギルド・キャッシュを含む全データは、稼働中でもSQLiteの整合性を保つ次のコマンドでバックアップできます。

```sh
node scripts/backup.mjs /absolute/path/guildwar-backup.sqlite
```

`DATABASE_PATH` を変更して運用している場合は同じ環境変数を指定します。バックアップファイルをホスト外にも保管してください。これは自動バックアップのスケジューラーではありません。

復元時はアプリを停止し、現在のDBと付属の `-wal` / `-shm` を別の場所へ退避してから、バックアップを `DATABASE_PATH` の位置にコピーし、起動します。起動時に必要なテーブルは作成されます。ホストのディスク自体が失われた場合は、別に保管したバックアップが必要です。

## 環境変数

`.env.example` を参照してください。Node.jsは `.env` を自動読込しません。`.env` を使う場合は `node --env-file=.env server/index.mjs` を実行します。

- `PORT`（初期値3000）、`HOST`（初期値0.0.0.0）
- `DATABASE_PATH`（初期値`./data/guildwar.sqlite`）
- `GUILD_SOURCE_URL`、`GUILD_FALLBACK_URL`：一覧の取得元と任意の予備取得先。予備取得先は初期値なし。
- `MEMBER_SOURCE_URL`：任意の独立した名簿API。例：`https://your-provider.example/guilds/{gid}/members`。空ならRangerbookの公開配信を使用。`members` 配列または配列そのものを返すAPIに対応し、各要素は `uid, userName, level, pvpLeaguePhase`。手動編集した名簿を優先します。
- `WRITE_TOKEN`：任意。設定すると保存にキーが必要です。画面の「使い方・保存設定」で入力します。キーはブラウザーのセッション内だけに保存されます。空の場合は元サイトと同様、共有編集です。

## 公開・永続化

### Render

`render.yaml` がBlueprint定義です。GitHubにこのコードを配置後、Renderの「New → Blueprint」でリポジトリを接続します。`/var/data` の永続ディスクにチェックとキャッシュを保存します。ディスク付きのStarterプランは有料です。**このコードの作成時点ではRenderへの作成・課金は実行していません。**

SQLite版は1インスタンスで実行してください。複数インスタンスを使う場合は共通のPostgreSQLなどへ保存層を変更します。単なる静的ホスティングやGitHub Pagesだけでは共有保存APIを実行できません。

### Docker

```sh
docker build -t line-rangers-guildwar .
docker run --rm -p 3000:3000 -v guildwar-data:/app/data line-rangers-guildwar
```

ボリューム・ディスクを省略すると、コンテナやホストの交換時に記録が失われます。バックアップは実行中のSQLiteファイルだけを単独コピーせず、SQLiteのバックアップ機能か停止時のDBを使用してください。

## 検証

```sh
npm test
npm run build
# npm start が別ターミナルで実行中の場合
npm run check:live
```

自動テストはJST09:00と週境界、年越し、ギルド・チーム・週の分離、保存後のDB再オープン、再送の冪等性、2回目と1回目の整合性、認証・送信元・入力検証、CSV数式対策を確認します。さらに全外部サービス停止状態での新規登録・名簿更新・攻撃記録保持・キャッシュ移行・SQLiteバックアップを検証します。
